# Query benchmarks

Median of 10 runs after 2 warm-up runs. Generated by `make bench`.

| Case | Before | After | Speed-up | db hits before -> after |
|---|---|---|---|---|
| Range filter: no index vs range index | no index: 32.1 ms | range index: 7.4 ms | x4.3 | 242,473 -> 1,345 |
| Optional filters: `$x IS NULL OR` vs query built from needed clauses | catch-all WHERE: 54.9 ms | rewritten: 9.1 ms | x6.0 | 317,731 -> 6,731 |
| Wine detail (correctness trade-off): OPTIONAL MATCH chain vs pattern comprehensions | OPTIONAL MATCH chain: 3.2 ms | pattern comprehensions: 3.0 ms | x1.1 | 146 -> 189 |
| Pagination: full result vs SKIP/LIMIT | no pagination: 2285.6 ms | LIMIT 20: 3.4 ms | x675.1 | 323,536 -> 61 |

## Range filter: no index vs range index

Without an index the planner scans every Wine node; with a range index it seeks.

- **no index** plan: ProduceResults > Projection > Top > Projection > Filter > NodeByLabelScan
- **range index** plan: ProduceResults > Projection > Limit > Filter > NodeIndexSeekByRange

## Optional filters: `$x IS NULL OR` vs query built from needed clauses

Both return the same columns for the same filters (points >= 95, price <= 30). `$x IS NULL OR w.points >= $x` cannot be answered from an index, so the planner scans every Wine; building only the needed clauses lets it seek on the points index.

- **catch-all WHERE** plan: ProduceResults > Projection > CacheProperties > Skip > Top > Projection > Filter > NodeByLabelScan
- **rewritten** plan: ProduceResults > Projection > CacheProperties > Skip > Limit > Distinct > PartialSort > Projection > Filter > NodeIndexSeekByRange

## Wine detail (correctness trade-off): OPTIONAL MATCH chain vs pattern comprehensions

For a single wine both are a few milliseconds: the chain only multiplies rows by the number of notes, which is small. Pattern comprehensions are kept for correctness, not speed: they never duplicate rows, so no collect()/DISTINCT is needed, which matters in list queries where several multi-valued relationships are combined.

- **OPTIONAL MATCH chain** plan: ProduceResults > EagerAggregation > OptionalExpand(All) > CacheProperties > OptionalExpand(All) > OptionalExpand(All) > OptionalExpand(All) > Apply > NodeUniqueIndexSeek > Optional > CacheProperties > Filter > VarLengthExpand(All) > Expand(All) > Argument
- **pattern comprehensions** plan: ProduceResults > Projection > CacheProperties > RollUpApply > NodeUniqueIndexSeek > Projection > Filter > Expand(All) > Argument

## Pagination: full result vs SKIP/LIMIT

Returning every match transfers and serialises thousands of rows; a page of 20 lets the planner stop early (Top-K sort).

- **no pagination** plan: ProduceResults > Projection > CacheProperties > NodeIndexSeekByRange
- **LIMIT 20** plan: ProduceResults > Projection > CacheProperties > Skip > Limit > NodeIndexSeekByRange
